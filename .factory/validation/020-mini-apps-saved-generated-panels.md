## Adaptations

- **Actions from an app window go through the launcher.** 019 keeps every action RPC launcher-only (verified by the 019 security review: "cannot act from a board window"). A window never prepares or executes: `stageMiniAppAction` (bun checks the app and action exist) navigates the launcher to a `mini-app-action` view, which calls `prepareMiniAppAction` (launcher-only) → 019's confirm sheet → `executeAction({ token })`. Bun maps the token back to the app and broadcasts `miniAppRefresh` with `refreshAfter`. Window runs of saved apps now also fill the run cache (owner `app:<id>/<source>`), so a compromised window renderer can stage a reviewed read/link action with input values it picks (same as 019's accepted launcher residual) but cannot run a write without the launcher's confirm.
- **`MiniApp.actions` are 019 `ActionDef`s with their review hash**; generated drafts carry `AppActionDraft` (`ActionDraft` + an element-key-style id). Save stamps them through 019's `stampReviewed`.
- **Subpath exports** `@conch/rpc/mini-app` and `@conch/core/mini-apps` instead of the root barrels: the renderer's static import of `@conch/rpc` would otherwise pull the zod contracts into the main chunk (+11 KB), and core's barrel hit the 100-module lint limit. The browser stub's mini-app emulator loads lazily for the same reason.
- `toggleLauncher({ fromBoardId })` → `{ fromWindowKey }`; `FocusState` uses window keys; boards keep bare ids as keys so `board-frames.json` still restores.
- "New App" with no prompt and "Change with a Prompt…" open a prompt field inside the generate view. The empty-apps tip ("Describe a tool and press ↵ on Build an app") renders as a `tip` note above the typed results.
- A card whose source was removed shows "This server was removed." / "This part's connection no longer exists."; the widget-style connection rebind is not offered in v1.

## Open items

- Desktop verification (all desktop done criteria), the 5-prompt model check, recordings, Timelines, a11y toggles.
- `nativeConfirm` runs dialogs through the launcher's `runModal`, which re-activates the launcher afterwards; saving a changed write action from an app window may surface the launcher (untested on desktop).
- The run cache keeps 20 runs across launcher widgets and app windows; a busy app window can expire a launcher row selection sooner.
- Edit mode has no pointer drag; cancel has no reverse-order fade.
- A security re-review of the mini-app surface (staging path, run cache owners, save gate) is recommended before merge.

## Security remediation (2026-11-22)

All four Low findings in `../security/scans/20261122-020-mini-apps/report.md` and both cheap deferred items are fixed; the per-finding table with proving tests is in that report under "Remediation status". Choice for SEC-020-02/03: app windows keep saving, but bun refuses any new or changed source, action or input from a window unless it came from a draft bun generated for that app (`fromGenId`); duplicate and delete are launcher-only; staging is bound to the app's own focused window by bun, rate-limited, never replaces a confirm sheet, and a staged link waits for one press in the launcher. Every non-copy action now needs its review tick, and the sheet shows the full URL template with query and each bound value source.
