### Suggested fixes

- SEC-019-01/02: make the lexer handle nested block comments for postgresql, duckdb and tsql (or reject any `/*` inside a comment); on Postgres send read-only SQL over the extended protocol and reject multi-result replies; for writes, reject function calls outside an allow-list in the parse tree.
- SEC-019-03: store a fingerprint of the target with each permission (host, port, database, user; endpoint origin; MCP launch line), drop the permission when it changes, and clear endpoint auth when the origin changes.
- SEC-019-04: delete the RPC or allow only `https:`/`mailto:`.
- SEC-019-05: native confirm on `resetSecrets`, or keep the audit log across a reset.
- SEC-019-06: run successful response text through `withoutSecret` before returning it.

## Informational

- Postgres `executeWrite` treats a multi-result reply as 0 rows (`rowCount ?? 0`).
- The native save dialog does not show bindings or `target.database`.
- Cascades and triggers are not counted against the row limit.
- GET and `readOnlyHint` actions skip the confirm sheet by design.
- The audit file is created with default permissions, not 0600.

## Deferred

- MSSQL dynamic checks (no fixture); MySQL `executeWrite` on a live server; macOS key handling in the native dialog; `listTools` caching; lookalike characters in row values on the confirm sheet; plan 018 keeping the auth header when `baseUrl` changes.

## T3 / T7 residuals (explicitly reviewed)

T3: a compromised renderer can self-confirm existing reviewed actions with input values it chooses, pick any cached row of the same widget, and spam native dialogs; this matches the accepted residual. It cannot enable writes, save a write action, supply row values, replay a token, or act from a board window. The review found three ways past the residual: repointing a write-enabled target (SEC-019-03), erasing the audit log (SEC-019-05) and writing to Postgres through `>` SQL without opt-in (SEC-019-01).

T7: the open-url action path is sound (https only at save and after the URL is built, fixed origin and base path, whole encoded values, `.`/`..` rejected). The remaining T7 risk is the unused `openExternal` RPC (SEC-019-04).

New findings:

- **SEC-019-10 (Medium, CONFIRMED on the Postgres fixture). The read-path server-call deny-list is bypassed by `U&"…"` Unicode-escape identifiers.**
  - Cause: `quotedName` does not decode `U&` escapes. An escaped `pg_read_file` (also schema-qualified) and `set_config(…, false)` passed `assertReadOnly`, and both ran through `PostgresPool.execute(readOnly)`. The server file contents came back, and the GUC was set at session level on the pooled connection.
  - Impact: the same calls work through any `U&`-escaped name, including `dblink_exec` if that extension is installed. Each needs a privileged role or an installed extension, which the threat model rates Medium.
  - Fix: refuse `U&` identifiers and strings on postgresql/duckdb (DuckDB already fails to parse them), or decode the escapes before matching. Add `U&` and forbidden-call probes to the differential generator.
- **SEC-019-11 (Low, CONFIRMED at the guard). T-SQL bracket identifiers ignore the `]]` escape.**
  - Cause: `literalAt` uses `indexOf("]")`. A quote inside `[a]] ' ]` opens a "string" for the guard that hides code the engine reads.
  - What still holds: stacking is refused by the one-statement parse rule.
  - What gets through: in-statement content hidden from the lexical deny-lists still passes `assertReadOnly`. A probe column was accepted. On the write path, the AST allow-list still applies.
  - Fix: honour `]]` the same way `closingQuote` honours doubled quotes.
- **Info.** These read paths pass:

  - `current_setting('data_directory')`: read-only.
