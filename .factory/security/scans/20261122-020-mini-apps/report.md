### Details and suggested fixes

- SEC-020-01: `applyDraftPatch` caps elements at 24 but never runs `panelProblems` (cycle/depth); the renderer walks with no visited set or depth cap. A bun script showed cyclic ops accepted; a browser test with `a → [a]` crashed the page (control rendered in 44 ms). Nothing persists (saved apps pass the cycle check). Fix: visited set + `MAX_PANEL_DEPTH` in the renderer walk; reject cycle-forming ops in the patch step.
- SEC-020-02: a compromised window (renderer XSS) can stage actions in a loop. Writes still stop at the confirm sheet; `executeAction`/`prepareMiniAppAction` stay launcher-only; a stage during an open mini-app sheet is dropped, but a stage replaces other launcher views including a widget write sheet. Fix: accept a stage only from that app's own, recently focused window; rate-limit; one-key confirm for open-url; never reset the stack while a confirm sheet is open.
- SEC-020-03: chains with 02 (define read SQL source + open-url action to any https origin, run the source to fill the run cache, stage the action → launcher opens a URL with row data, no click). Fix: make `saveMiniApp`/`duplicateMiniApp`/`deleteMiniApp` launcher-only, or refuse new/changed actions and sources when the save comes from a window.
- SEC-020-04: `catalogProblem` checks only sources, not action targets. Fix: show the full URL template (with query) in the review sheet and native dialog, and require a review tick for generated external actions or limit them to catalog origins.

## Accepted residuals and notes

- `saveMiniApp` persists the renderer-sent draft (plan contract); the runner still forces every source to be read-only.
- The review hash covers the action alone; an edit can change which source's rows or which input feeds it, but every run shows bound values on the confirm sheet.
- Duplicating an app copies its reviewed write actions unchanged.
- Audit entries for mini-app actions have `widgetId: null` and don't name the app.
- During a build, bun runs model-chosen read calls against `readOnlyHint` MCP tools and HTTP GET endpoints (by design).
- Generation events (including result rows) are broadcast to every window.
- Any window can fill the 20-run cache; ownership checks stop cross-app rows.
- Window keys can be spoofed, which only changes which window gets focus.
- Any window can start a build (AI spend).

## Verified invariants

- Generation ports are only model, `runSource` and `now`; catalog and read checks apply in the generator and again in the runner.
- Patches: allow-listed paths only; `__proto__`/`constructor`/`prototype` rejected; every value zod-parsed; line, element, source and action limits.
- Runs and prepares use the saved app from `mini-apps.enc` or bun's own draft (only after a clean build); input values validated against `ParamDef` and bound as parameters.
- Writes: native dialog and opt-in at save; opt-in at prepare and execute; reload plus review-hash and call-hash re-check at execute.
- Rendering: no `dangerouslySetInnerHTML` or `href`, nothing styled from spec text, an error boundary per element.
- `mini-apps.enc` is encrypted and holds no rows; `conch-link`, `link-router` and the plan-016 MCP server cannot reach mini-apps.
