## Direction: oh-my-query becomes a database launcher

oh-my-query becomes a Raycast-style launcher for databases. A global hotkey
summons a translucent panel. You type a question, and it streams the SQL, runs
it read-only, and answers with a chart card. Answers can be saved as widgets
with typed inputs, and widgets can be composed into live boards. The reference
is the owner's demo video. It shows four stages: the input with an `analytics`
chip, "Generated SQL · PostgreSQL" streaming, "Running query · Read only", and
a Bar/Line/Table card with a legend and a one-line insight.

The owner made these decisions on 2026-11-17:

Every UI plan (002, 003, 005, 006, 007) has a motion table listing each moment's trigger, what moves, its token and its reduced-motion fallback. Motion is never cut to hit a deadline; a plan stops and reports instead. |

Decisions made on 2026-11-19 for plans 008–020:

| Decision    | Choice                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Scope       | Every item in [next-opportunities.md](next-opportunities.md) became a plan (008–020).                                                                                                                                                                                                                                                                                                                                                                                                |
| Writes      | **Allowed, gated.** Asks and widget runs stay read-only forever. Writes exist only as declared actions (plan 019): `effect: read \| write \| external`; every `write` shows a confirm sheet with the exact target and bound values; SQL writes need a per-connection "Allow write actions" opt-in (default off) and a human-reviewed statement template; values bind as parameters; every write is audited in `actions-audit.enc`. MCP tools without `readOnlyHint` count as writes. |
| MCP server  | **Yes.** Opt-in, per-connection exposure off by default, read-only tools only, credentials never leave bun, every call audited (plan 016).                                                                                                                                                                                                                                                                                                                                           |
| json-render | Not for cards, widgets or boards (`CardSpec` stays). Possible renderer for mini-apps only, decided by plan 020's one-day spike. The saved mini-app format is ours either way.                                                                                                                                                                                                                                                                                                        |

Decisions made on 2026-11-21 for plans 021–023, from a study of Raycast's
panel (owner screenshots plus a `cua-driver` session):

| Decision                  | Choice                                                                                                                                                                                            |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| What we take from Raycast | Structure and behaviour: one surface, floating footer, steady height while typing, one ranked list, actions on every row, a searchable action panel, drafts. Not its look.                        |
| What stays Conch          | The amber selection, one selection that follows the pointer, the armed two-press confirm, the ask flow's height morph, and "↵ on a typed question asks".                                          |
| Panel height              | Content-sized, but the root and History hold their height while a query is typed (plan 021). A single fixed height for every view was rejected because the ask morph needs a content-sized panel. |
| Typed results             | Ask and Look up rows stay first; everything below is one ranked "Results" list with a kind label per row (plan 022).                                                                              |
| `⌘↵` at the root          | Runs the row's second action (plan 023). Raycast's `⌥↵` "keep the window open" is not adopted: Conch's row actions already keep the panel open.                                                   |

## Findings considered and rejected

- **Keep `@json-render/*` for generative UI.** Rejected. Its free-form trees
  embed data, so saved widgets and boards could not re-run SQL against fresh
  data. A data-bound `CardSpec` replaces it. (Re-evaluated 2026-11-19: specs
  holding only `$state` pointers can re-render on fresh data, so json-render
  is back on the table as a possible renderer for mini-apps, not for cards. See
  [next-opportunities.md](next-opportunities.md) §1.)

- **Open-ended tool-calling agent loop.** Rejected for v1. A fixed pipeline
  (schema → SQL → guard → run → present, with up to 2 repairs) maps one-to-one
  onto the demo's visible phases. It is deterministic to test and cheaper per
  ask.
- **String-substituted widget parameters.** Rejected. Values are always
  driver bind parameters (plan 006).
- **Installing the uiarc/uai registries.** Rejected by the owner's choice.
  Arc's AI blocks are paid Pro, and Uai's palette is cool blue, which is
  off-brand.
- **`apps/web/`.** Leftover Tauri/Storybook residue with no `package.json`.
  It is not part of this roadmap; delete it separately if wanted.
